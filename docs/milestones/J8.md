# JARVIS phase 8: Hermes ("no skill for that → request one", risk analysis in review)

Architecture row: "'no skill for that → request one', permission analysis in review; risk:
generated code; review flow stays mandatory". Nothing here lets Hermes do more: it can still
only write files into `skills/_incoming`, and nothing it writes runs until you approve it.

## What is built
1. **FLINS offers to pass on what it can't do.** When the conversation model answers "I
   can't do that yet", FLINS may add: *Want me to pass this to Hermes as a skill request:
   "<your words>"? Say yes or no.* On **yes** a request file is written to
   `skills/_incoming/_requests/` (the same place "make a skill that ..." uses).
2. **Risk analysis on the review page.** Above the diff, a plain-language list of what the
   skill could do with the permissions it asks for, an overall risk (low / medium / high),
   and what is new compared with the version you approved before. Decided by code from the
   manifest, not by Hermes' own description.
3. **High risk needs a tick.** A skill whose replies could go out without you seeing them,
   or that can both read messages and reach the network, can only be approved with the
   "I understand" box ticked. The server enforces it, not the page.
4. `flins chat` and `flins ask` can also save a request (they share the same folder).

## Files
- `src/flins/skills/analysis.py`: `analyse(manifest, previous) -> Analysis`.
- `skilldev/review.py`: `ReviewView.analysis`; `approve(..., acknowledged=)`.
- `web/app.py`, `templates/skill_review.html`: the analysis block and the tick box.
- `core/commands.py`: `CommandRouter.request_skill`, `can_request_skill`.
- `assistant/core.py`: the offer. `settings.py`: `assistant.skill_requests`.
- `tests/unit/test_j8_hermes.py`.

## Rules (each has a test)
1. **Only your words go into a request**, and only after your yes. Not offered when a tool
   ran in that turn (so nothing a file or web page said can end up in a request), for
   secrets, or more than once per cooldown (30 minutes).
2. **The offer never replaces the honest answer.** "I can't do that yet" is still said.
3. **The analysis can't be talked down.** It reads the manifest; Hermes' summary is shown
   separately and labelled as unchecked.
4. **Approval is still tied to the exact files** (hash), still re-runs validation, fixtures
   and the full eval, and for high risk additionally needs the acknowledgement.
5. Invariants 8 and 9 unchanged: skills can't send; Hermes can't enable, edit policy or read
   `data/`.

## Not in this phase
- A skill can only react to incoming messages or the "summary" command. Requests for other
  things (a calendar, a cab) are saved honestly as requests; Hermes may not be able to
  build them. FLINS says "pass this to Hermes", not "I'll get this built".
