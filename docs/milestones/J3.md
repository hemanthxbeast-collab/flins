# JARVIS phase 3: tasks, reminders, planning

Goal: **FLINS can manage your work.** "Remind me at 7 to call the bank" becomes a real reminder
that fires; "what should I work on?" is answered from your actual task list.

Built in two steps so each stays small and tested.

## 3a: tasks, reminders, scheduler (this step)
| Piece | Files | Notes |
|---|---|---|
| Table | migration 0013 | `tasks`: title, notes, priority (low / normal / high), status (open / done / cancelled), due_at, remind_at, repeat (none / daily / weekdays / weekly), project, source, channel, created / updated / completed, last_reminded_at |

| CLI / dashboard | `flins tasks …`, `/tasks` | list, add, done, delete; the page shows open and recently done |

## 3b: planning (next step)
Plans as stored step lists with status per step, approval gates before any step that acts,
"execute the plan", dependencies between tasks. Needs tools (phase 4) to be worth much, so it
comes after 3a.

## Safety and honesty
- Creating a task or reminder is harmless and reversible, so it needs no confirmation; FLINS
  reads back what it understood ("Reminder set for today 19:00: call the bank").
- A time it can't parse is never guessed: FLINS asks "When?".
- Reminders are notes to **you** only. They never send anything to a contact.
- The conversation model still can't claim it set something: tasks are created only by these
  commands, the CLI or the dashboard.

## Tests
time phrases (including "at 7" picking the next 7 o'clock, past times rolling to tomorrow);
add / list / done / delete / snooze; repeats; reminders fire once, survive a restart, are held
while paused and quiet in focus; no model call for any of it; context block; CLI; dashboard.
