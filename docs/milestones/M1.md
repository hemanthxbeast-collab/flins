# M1: WhatsApp sidecar (read-only)

## Goal
FLINS pairs as a linked device, receives messages and contacts, stores them, and shows a live
feed. **It cannot send anything.** The sidecar has no send command, and the core adapter's
`send_text` raises `NotImplementedError` until M4.

## Pieces
| Piece | Files | Notes |
|---|---|---|
| Sidecar | `wa-sidecar/src/{index,protocol,mapping,server}.ts` | Node + TypeScript, `@whiskeysockets/baileys@7.0.0-rc14` pinned exactly (versions before rc12 have a message-spoofing bug, GHSA-qvv5-jq5g-4cgg). |
| Wire protocol | `wa-sidecar/src/protocol.ts`, `src/flins/adapters/protocol.py` | Same rules on both sides, checked by shared test vectors in `tests/fixtures/protocol_vectors.json`. |
| Core adapter | `src/flins/adapters/{base,baileys,fake,sidecar_proc}.py` | `MessagingAdapter` protocol, a WebSocket client with reconnect, a fake for tests, and a helper that starts the sidecar process. |
| Ingest | `src/flins/core/ingest.py`, migration `0002_contacts_lid.sql` | Stores messages (deduplicated), creates and merges contacts, imports the address book, publishes bus events, audits connection changes. |
| CLI | `flins wa pair`, `flins wa tail` | `pair` shows the QR in the terminal. `tail` starts the sidecar if needed, ingests, and prints the feed. |

## Wire protocol v1
- Transport: WebSocket on `127.0.0.1:<sidecar_port>` only. One client at a time.
- Each frame is `{"body": "<json string>", "sig": "<hex HMAC-SHA256(FLINS_WA_SECRET, body)>"}`.
- `body` = `{"v": 1, "kind": str, "id": str, "ts": epoch_ms, "payload": {...}}`.
- The receiver rejects a frame with a bad signature (constant-time compare), `|now − ts| > 120 s`,
  an `id` it has already seen (it remembers the last 2000), or `v ≠ 1`.
- Handshake: core → `hello`. Sidecar → `hello.ok` with the current WhatsApp state, then sends any
  events it buffered while no client was connected (up to 1000). A wrong or missing hello closes
  the socket with code 4401. A second client gets 4409.
- Sidecar → core: `hello.ok`, `connection`, `message.received`, `contacts.upsert`, `pong`.
- Core → sidecar: `hello`, `ping`. **There is no send command in v1.**

## Identity (phone number vs LID)
WhatsApp now often addresses people by a LID (`…@lid`) instead of their phone number JID
(`…@s.whatsapp.net`). Baileys gives the other form in `remoteJidAlt` / `participantAlt` when it
knows it, and the sidecar also asks Baileys' LID mapping store. The core uses the phone-number JID
as `contacts.wa_jid` when it's known, keeps the LID in `contacts.wa_lid`, and merges a LID-only row
into its phone-number form once the mapping appears.

## Behaviour choices
- `markOnlineOnConnect: false`, so the phone keeps getting notifications. No read receipts.
- `syncFullHistory: false`. History sync is used for **contacts only**, not old messages.
- Status updates, broadcast lists and channels are ignored in the sidecar and again in the core.
- Own messages sent from the phone are stored as `direction = OUT` (context for later), never as triggers.
- Disconnect handling:
  - `loggedOut` (401), `forbidden` (403), `multideviceMismatch` (411): emit `logged_out`, move the
    auth folder aside, stop. You re-pair.
  - `connectionReplaced` (440): emit `conflict`, stop. Another WhatsApp Web client took over (for
    example, Hermes' gateway left on).
  - `restartRequired` (515): reconnect immediately (normal right after pairing).
  - Anything else: reconnect with backoff 1 s → 60 s.
- The sidecar never logs message text. Baileys' own logger runs at `warn`.

## Tests
- Python: protocol (round trip, tampering, wrong secret, stale, replay, version, shared vectors);
  ingest (dedupe, filters, OUT messages, unknown → `unknown` tier, address book → `known`, user
  tiers never overwritten, LID → phone merge, bus event only on new rows); adapter against a fake
  sidecar server (handshake, typed events, forged frames dropped, reconnect, `send_text` refuses);
  a code scan proving nothing outside `adapters/` calls `send_text`.
- Node (`node --test`): protocol + shared vectors; Baileys message → event mapping for text,
  quoted text with mentions, captioned image, reaction, LID with alt, skipped protocol messages.

## Demo
```powershell
npm --prefix wa-sidecar install
npm --prefix wa-sidecar run build
uv run flins wa pair      # scan the QR: WhatsApp > Linked devices > Link a device
uv run flins wa tail      # send yourself a message from another phone and watch it appear
```
