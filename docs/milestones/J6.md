# JARVIS phase 6a: your chats, read-only ("what did X say", "reply to him")

Phase 6 is the most safety-sensitive phase, so it is split:
- **6a (this document):** you can ask FLINS about one person's chat and answer it by voice or
  text. Nothing about how incoming messages are decided changes.
- **6b (next):** more modes (DND, sleep, travel, custom), per-contact topic permissions, HOLD.
  That changes the policy engine, so the eval set grows first.

## What you can say
| You say | FLINS does |
|---|---|
| "what did Rahul say?", "any messages from mom?", "read Rahul's chat" | reads out the last messages of that chat, word for word. No AI model involved |
| "summarise Rahul's chat", "summary of the chat with mom" | a short summary from the `summary` model, plus what they want from you |
| "reply to him I'll call at 8", "tell her I'm on my way" | the normal send flow: read back, **yes / no**, then the Outbox |
| "reply to Rahul saying I'll call at 8" | the same, by name |

"him / her / them" means the person whose chat you just asked about (for 10 minutes).

## Files
- `src/flins/assistant/chats.py`: `ChatReader` (SQL, read-only), `ThreadSummariser`,
  `ChatCommands` (fixed phrases, like the task and memory commands).
- `prompts/thread_v1.md`: the summary prompt. `prompts/chat_v7.md`: tells the conversation
  model these phrases exist.
- `core/commands.py`: `CommandRouter.send(spoken, text, source)`, the public door to the
  existing confirm-then-Outbox flow.
- `assistant/core.py`: step 0 runs the chat commands; `Reply.stored`.
- `settings.py`: `assistant.chats` (`enabled`, `max_messages`, `days`, `summarise`).
- `tests/unit/test_j6_chats.py`.

## Rules (each has a test)
1. **Read-only.** `chats.py` only SELECTs. It imports neither the adapter nor the Outbox;
   sending goes through `CommandRouter.send`, which reads the message back and waits for yes.
2. **A reply is only ever your words.** FLINS never drafts a reply from what the contact
   wrote here. "reply to him" with no message asks "What should I tell Rahul?".
3. **Contact text is untrusted.** For a summary it goes to the model inside
   `<untrusted_thread>`, neutralised, with no tools. The model returns three plain fields.
4. **It does not leak into the conversation.** What a contact wrote, and the summary made
   from it, are shown to you but stored in the conversation history as a placeholder
   ("[Read out 3 messages from the chat with Rahul.]"). So a message can't later instruct
   the conversation model, which has tools.
5. **No guessing who.** No match: says so. Several matches: asks which. A pronoun with nobody
   in mind: asks for the name. "What did Einstein say" (not a contact) is left to the
   conversation.
6. **Only when you are talking to FLINS.** In your self-chat these phrases count only when
   addressed to FLINS, like the other commands.
7. **Codes are not sent to the summary model.** Digits in a line that mentions an OTP, PIN,
   password or code are replaced before the model sees it. A chat that mentions money or
   codes gets a "read it yourself before acting" line, decided by code.
8. **Audit:** one `assistant.chat_read` row per use: kind, contact id, message count. No
   names, no text.

## Not in 6a
- Follow-up questions about a chat ("what does he mean?") can't be answered, because of
  rule 4. Ask for the read-out or the summary again.
- Group chats, searching across chats, media.
