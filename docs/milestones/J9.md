# JARVIS phase 9: polish (home, activity, automations)

Architecture row: "home / status / activity / memory browser / automations; risk: none".
The dashboard grew a page per phase; this adds the three that tie it together. The memory
browser already exists (`/memory`, phase 2).

## What is built
- **Home** (`/home`, first in the menu): one screen that answers "what is FLINS doing right
  now?": mode, sending on or dry run, drafts waiting, who is on hold, today's tasks, what is
  switched on (voice follow-up, briefings, tools, online tools, chats), skills waiting for
  review, and the last few things it did.
- **Activity** (`/activity`): the audit log, newest first, with a filter by kind. Audit rows
  never contain message text, titles or names (by design since M0), so this page is safe to
  leave open.
- **Automations** (`/automations`): everything that happens without you asking, in one
  place: repeating reminders, briefings and their times, the modes you defined and their
  phrases, holds (with a Release button), per-contact topic limits, and enabled skills.

`/` stays the Inbox, so existing links keep working.

## Files
- `web/app.py`: three GET routes, `POST /holds/release`.
- `web/templates/home.html`, `activity.html`, `automations.html`; `base.html` menu.
- `core/commands.py`: holds are now audited (`hold.set`, `hold.released`).
- `tests/unit/test_j9_dashboard.py`.

## Rules
1. Pages are read-only except Release hold, which needs the page token like every other form.
2. Loosening anything else (topic limits, policy, switching features on) stays in the config
   files and the CLI.
3. The same host check, headers and content security policy as every page; no scripts.
