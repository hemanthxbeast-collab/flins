# M2: Modes, commands, hard rules, decide()

## Goal
FLINS knows what mode it's in ("working mood", focus, away, paused), changes mode on command
from the CLI or the WhatsApp self-chat, and for every incoming message computes **what it would
do** with a pure, fully traced `decide()` function. **Nothing is sent.** There's no drafter
(M3) and no outbox (M4) yet, so decisions are recorded and shown, never acted on.

## Pieces
| Piece | Files | Notes |
|---|---|---|
| Clock | `core/clock.py` | `SystemClock` and `FrozenClock`. Everything time-based takes a clock. |
| Mode FSM | `core/modes.py`, migration `0004_mode_state.sql` | Explicit `TRANSITIONS` table. A `ModeManager` persists state in SQLite inside `BEGIN IMMEDIATE`, so the CLI and `flins run` can both change modes safely. |
| Readbacks | `core/readback.py` | Fixed text for every transition and for status. No LLM. |
| Grammar (Tier A) | `core/grammar.py` | Anchored phrases with optional durations and profiles. Shared by CLI, self-chat, and voice later. |
| Triage types | `core/triage.py` | `TriageResult` model. M2 has no LLM triage; a deterministic fallback derives the category for media and hard-rule hits. |
| Hard rules + decide | `core/policy.py` | `evaluate_hard_rules()` and `decide()`. Pure functions: inputs in, `Decision` with full ceiling trace out. |
| Pipeline | `core/pipeline.py` | On `wa.message`: loads context, runs rules + decide, writes `bursts`/`decisions`/`audit_log`, publishes `decision.made`. Self-chat messages go to the command router instead. |
| Commands | `core/commands.py` | Turns a parsed command into mode transitions and reply text. |
| Replay harness | `src/flins/replay.py`, `tests/replay/*.jsonl` | Scripted streams with a frozen clock through the real ingest, pipeline and mode code. |
| CLI | `flins run`, `flins mode <text>`, `flins stop` | `run` = sidecar + ingest + pipeline + self-chat commands + expiry ticks. |

## Mode state machine
| From \ Event | ENTER_WORKING / FOCUS / AWAY | EXIT_TO_NORMAL | EXTEND | EXPIRE | CANCEL (≤10 s) | KILL | RESUME |
|---|---|---|---|---|---|---|---|
| NORMAL | → that mode | — (no-op) | ✗ | ✗ | ✗ | → PAUSED | ✗ |
| WORKING/FOCUS/AWAY | → that mode (new `until`) | → NORMAL | same mode, new `until` | → NORMAL (only once `until` has passed) | → previous state | → PAUSED | ✗ |
| PAUSED | ✗ | ✗ | ✗ | ✗ | ✗ | PAUSED (no-op) | → previous mode if its `until` is still ahead, else NORMAL |

✗ = rejected with a clear message. PAUSED only answers "resume" (SPEC §3.1).

Guards:
- Timed modes need `until` in the future and **at most 12 h ahead**.
- On load, an expired timed mode becomes NORMAL (source `restart`). A crash never extends autonomy.
- `decide()` treats an expired-but-not-yet-ticked mode as NORMAL.
- A warning event fires once, 10 minutes before `until`.

## decide()
`final = min(mode, tier, contact.max_level, allowed_categories, category, sensitivity flags,
triage, skill, budget, hard rules, AUTO_SAFE template availability)`. Each term is recorded by name in
`decisions.ceilings`. Hard-NOTIFY categories and flags are clamped **in code as well as config**
(invariant 7). Triage can only add terms, so it can only lower the result (invariant 1).

Hard rules (SPEC §7.3), all evaluated. The cap is the **lowest** of all hits (more cautious than
"first match"), and flags are the union:
`paused`, `blocked`, `group`, `credentials`, `money`, `emergency` (escalate), `contact_rate`,
`loop`, `backlog`.

## Tests
- Transition table: every (mode, event) pair is either listed or rejected; restart after expiry
  → NORMAL; cancel window; resume rules; 12 h cap; cross-process change through the DB.
- Grammar: positive and negative phrase table, durations ("till 6pm", "for 90 minutes", "till 6"
  → next 6 o'clock), profiles, approvals, and no false triggers on ordinary sentences.
- Hard rules: table-driven cases in `tests/fixtures/hard_rule_cases.jsonl`, all must pass.
- decide(): invariant 7 clamp even with a malicious config, triage can't raise, expired mode →
  NORMAL ceiling, AUTO_SAFE without a template falls to NOTIFY, profile overlays.
- Replay: the CLAUDE.md "working mood" path, steps 1–8. Triage is injected per message, and
  "would send" stands in for sending.

## Demo
```powershell
uv run flins mode "I'm in working mood till 6pm"
uv run flins mode status
uv run flins stop
uv run flins mode resume
uv run flins run          # then type "status" or "focus mode for 1h" in your WhatsApp "Message yourself" chat
```
