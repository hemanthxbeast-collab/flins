# M9: Earned auto replies, tone learning, wake word, autostart, backups

## 1. Free-form AUTO replies, earned per contact
Today an AUTO decision still waits for your approval; only fixed holding templates go out by
themselves. M9 lets an AI-written reply go out unreviewed, but only when **all** of these hold:

| Check | Where |
|---|---|
| `auto_replies: unlocked` in policy.yaml (default stays `holding_only`) | policy |
| You opted this contact in (`flins contacts auto "Meera" on`, or the dashboard) | `contacts.auto_optin` (migration 0010) |
| ≥ 20 of FLINS's AI drafts for this contact approved, and ≤ 10% of them edited or rejected | `core/autonomy.py`, counted from approvals |
| The decision itself is AUTO (tier, mode, category, sensitivity, triage: unchanged rules) | `decide()` |
| Output guard passed, red-flag check ran and said safe (no red-flag check → no unreviewed send) | pipeline |
| Outbox checks at send time: not paused, mode still on, contact wrote in 24 h, you haven't replied, rate limits, dry_run | outbox (`kind = auto`) |

`policy.yaml` can make the bar higher (`auto_unlock: {min_approved, max_edit_rate}`) but not lower:
values below 20 / above 10% are clamped with a warning. Money, OTPs, legal/medical and conflict stay
NOTIFY whatever happens (invariant 7). Opting in never happens automatically.

## 2. Tone learning
Your edits (draft → what you actually sent) are already stored in `tone_examples`. The drafter now
gets the latest ones for this contact (5, plus 3 from anyone) in a separate, neutralised
`<your_edits>` block, with prompt `draft_v3` telling it to copy the style, never the facts.

## 3. Encrypted backups
`flins backup` → a consistent SQLite snapshot (backup API), encrypted with AES-256-GCM. The key
comes from a passphrase via scrypt; the passphrase is `FLINS_BACKUP_PASSPHRASE` in `.env`.
`flins backup restore <file>` decrypts into a new file and never overwrites your live database.
`flins backup --keep 14` keeps the newest backups. Uses `cryptography` (you approved the
dependency).

## 4. Windows autostart
`flins autostart on | off | status` creates/removes a Task Scheduler task that runs `flins run`
(optionally `--voice`) at your logon, as you, not elevated. Also `scripts/autostart.ps1`.

## 5. Wake word ("FLINS")
`openwakeword` can't install on Python 3.13 (it needs `tflite-runtime`, which stops at 3.11), and
has no "FLINS" model anyway. Instead: a mic listener that only wakes on speech (loudness gate),
transcribes short bursts with Whisper `tiny` locally, and checks whether one starts with "FLINS"
(or a sound-alike: flints, flinz, plins…). Then it records the command as push-to-talk does.
Off by default (`voice.wake_word: true`). Audio is never saved.
