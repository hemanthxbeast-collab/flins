# J4: tools (JARVIS phase 4)

Goal: FLINS can use tools to answer you: exact arithmetic, date maths, your notes, and files
in folders you approve. Split in two because the second half needs your choices.

## 4a (this milestone): the tool layer and the offline tools
| Piece | Where | Notes |
|---|---|---|
| Tool model | `assistant/tools/base.py` | A tool has a name, a one-line description, an input format (one string), a **risk** (`read` / `private` / `write`) and whether its result is **outside content** (text FLINS didn't write). `ToolBox` runs a tool with a timeout, catches errors and clips the result |
| How a tool gets used | `assistant/core.py`, `prompts/chat_v5.md` | The conversation model can *ask* for a tool (`tool`, `tool_input` in its JSON). Code checks the name against the allowed list, runs it, and gives the result back as data in `<tool_result>`; the model then answers. No extra model call on turns that need no tool. At most 2 tool rounds per turn |
| Risk gates | core | `read`: runs. `private` (your files): runs only inside folders you listed. `write` (add a note): never runs on the model's word; FLINS shows exactly what would be written and asks yes / no |
| Outside content rule | core | After a tool returns outside content (a file), the turn is "tainted": no further tool call and no memory suggestion in that turn, and the content is neutralised and marked as data. A file cannot make FLINS do anything |
| calculator | `tools/calc.py` | Safe expression evaluator (own parser on Python's `ast`, no `eval`): + - * / // % **, brackets, percent, sqrt / log / sin / …, pi, e. Size limits |
| date_math | `tools/dates.py` | now in a timezone; days between two dates; add days / weeks / months / years; weekday of a date |
| notes | `tools/notes.py` | `note_add` (write, confirmed) appends to `data/notes.md`; `notes_read` shows or searches it. Secrets are refused |
| files | `tools/files.py` | `files_list`, `files_search`, `files_read`: read-only, only under `assistant.tools.folders` (empty by default = off). Paths are resolved first (no `..` or symlink escape); hidden files, key / credential files and non-text files are refused; a file that looks like it holds credentials is refused; size and length caps |
| Config | `assistant.tools` | `enabled`, `allow` (tool names), `folders`, `max_rounds` |
| CLI | `flins tools` | lists tools, their risk and whether each is on; `flins tools run <name> <input>` to try one |
| Audit | `assistant.tool` rows | tool name, risk, ok, duration, sizes. Never the input or the result |

## Safety
- The model never executes anything: it names a tool and an input; code decides.
- No tool can send a message, change a mode, edit policy, or touch the WhatsApp pipeline.
  Tools are never available to the contact-reply models (invariant 5 unchanged).
- Write tools always confirm with the exact content. There is no "dangerous" tool yet.
- File contents go to whichever model answers the turn. If that is a cloud provider, the text
  of the file you asked about is sent there. That is why folders are opt-in and documented.
- Built-in tools run in-process: they are small, reviewed code in this repo. Third-party or
  generated tools must go through the skill sandbox and review (phase 8), not this path.

## 4b (next, needs your choices): online tools
Weather, web search and GitHub need network access, a provider and in some cases an API key.
Their results are outside content, and they add a way for text to leave the PC (a search
query), so they get their own risk level and are off by default.

## Tests
calculator correctness and limits (no names, attributes, huge powers); date maths; notes add
needs yes, refuses secrets; files confined to approved folders (`..`, absolute paths, symlinks,
hidden and credential files, binary, size); tool loop (result reaches the model, unknown or
disallowed tool, round cap, tool failure, timeout); taint blocks further tools and memory
suggestions; write gate; audit has no content; tools off in config; CLI; contact pipeline has
no access to tools.
