# M7: Skills

## Goal
Small add-ons ("skills") can suggest replies or facts, but they **never send** and **never get more
than they declared**. Each run happens in a separate, locked-down Python process. A skill only
runs after you have approved that exact version. Changing any of its files switches it off until you
approve it again.

Acceptance (SPEC §14): a skill calling a capability it didn't declare is **denied and logged**.

## Pieces
| Piece | Files | Notes |
|---|---|---|
| Manifest | `skills/manifest.py` | `flins.skill.yaml` schema (pydantic). Fixed permission list; **`wa:send` doesn't exist** and is rejected by name. `max_level` ≤ AUTO. |
| Contract | `skills/models.py` | `SkillInput`, `SkillOutput`, `Proposal` (reply / notify / note / calendar_hold). |
| Worker | `skills/worker_main.py` | Runs inside the child: `python -I -B`, empty env, cwd `data/skill_runs/<id>`. Python audit hook blocks sockets, subprocesses, ctypes, writes outside the run dir, reads outside the skill/Python folders (so no `data/`, no `.env`). `print` goes to the log, not the protocol. |
| Runtime | `skills/runtime.py` | Starts the worker, speaks JSON lines over stdin/stdout, enforces the timeout (kill), the output size, and validates the output. |
| Capabilities | `skills/ctx_api.py` | Core side of `ctx.*`. Every call checked against the manifest; a denial goes back to the skill as an error **and** writes `audit_log` `skill.denied`. |
| Validator | `skills/validator.py` | Schema, SKILL.md frontmatter, entrypoint exists, AST checks (imports from an **allowlist** of safe stdlib modules only, no `eval/exec/open/__import__`, no dunder tricks), ruff if available, permission diff vs the approved version. |
| Lock | `skills/lock.py` | `skills/skills.lock` (git-ignored, yours): name → version, sha256 of every file, permissions, network, max_level, approved_at. Hash mismatch → skill doesn't run. |
| Registry/engine | `skills/engine.py` | Loads skills, matches triggers (category + mode, or a command like `summary`), runs them, records `skill_runs`. |
| Pipeline | `core/pipeline.py` | After `decide()`, if the level is still ≥ AUTO_SAFE/DRAFT: run matching enabled skills. A reply proposal becomes the draft (source `skill:<name>`), with ceiling `skill = max_level`; facts go to the drafter and the guard. Then the usual guard / red flag / approval / outbox. Failure → normal path, with a warning. |
| CLI | `cli.py` | `flins skills list | validate <n> | test <n> | enable <n> | disable <n>`. Enabling shows permissions and asks you to type the skill name. |

## Capabilities (permission → `ctx` call)
| Permission | Call | Gives |
|---|---|---|
| `wa:read_thread` | `ctx.thread(n)` | last ≤ 20 messages of the current chat |
| `wa:propose_reply` | (output) | may return `reply` proposals; without it they're dropped and logged |
| `contacts:read_card` | (input) | first name, tier, language of the sender |
| `calendar:read` | `ctx.calendar.free_busy(start, end)` | busy intervals from your `.ics` file |
| `faq:read` | `ctx.faq()` | entries from `config/faq.yaml` |
| `messages:read_recent` | `ctx.messages.recent(hours)` | recent inbound messages with FLINS's decision (for "what did I miss") |
| `http:get` | `ctx.http.get(url)` | GET, only to hosts in `network:` |

`llm:complete` is recognised but **not available in M7** (validation error); `wa:send` never exists.

## Starter skills (`skills/`, shipped **disabled**)
1. `holding_reply`: mode-aware holding text. AUTO_SAFE.
2. `availability_reply`: reads busy times from an `.ics` file → `free_at` fact + suggested reply. DRAFT.
3. `whats_missed`: "what did I miss?" grouped by person, urgent first.
4. `faq_responder`: answers only from `config/faq.yaml`, only for the tiers each answer allows. DRAFT.
5. `eta_reply`: "where are you?" while AWAY. AUTO_SAFE.

## Tests (safety first)
Undeclared call denied + audited; `wa:send` rejected; reply without `wa:propose_reply` dropped;
sandbox blocks socket, subprocess, reading `data/`, writing outside the run dir (even for code
that skipped the validator); timeout kills; edited file → not run; a skill can't raise a level
(money / OTP never reach a skill); validator catches banned imports, eval, dunder escapes,
permission increases. Each starter skill: fixture tests through the real sandbox. Eval with all
starter skills in the loop: 0 unsafe.

## Demo
`flins skills list` → `flins skills test holding_reply` → `flins skills enable holding_reply` →
replay a working-mood message and see `skill:holding_reply` in the decision trace. Then edit the
skill's file, run `flins skills list` again, and see "changed since approval, not running".
